# Katwed visual language

Katwed's visual system is one product with three deliberately different contexts. Shared type, spacing, colour, radius, focus and motion tokens keep those contexts related without making them look identical.

## Pass 1 — design system

The foundation defines the Bricolage Grotesque display voice, semantic tokens and reusable buttons, fields, badges, timers, positional answer markers and answer tiles. Focus-visible and reduced-motion behaviour are part of those primitives, not page-level extras.

## Pass 2 — live stage

Presentation is the expressive, long-distance stage. Player is the compact, touch-first contestant control pad. Both share quiz themes, backgrounds, answer palettes and phase semantics while using layouts suited to their different viewing distances. See [Live-game visual language](live-game-visual-language.md).

## Pass 3 — backstage

Authenticated host tools use neutral, restrained application chrome. Quiz identity appears inside cards, pickers and previews rather than recolouring the workspace. The library, editor, settings and controller prioritise rapid scanning, clear primary actions and professional information density. See [Backstage visual language](backstage-visual-language.md).

## Pass 4 — public experience and cohesion

Landing, Join, authentication transitions, loading, recovery and Not Found states form the bridge between stage and backstage. They use recognisable Katwed branding with calmer surfaces and concise instructions. Whole-product polish preserves the established live geometry and host workflows while aligning navigation, form validation, status feedback, responsive behaviour and recovery copy.

The result keeps a clear relationship:

- public Katwed is welcoming and direct;
- live Katwed is bold and theatrical;
- backstage Katwed is quiet and productive.

New visual work should extend the shared system and the appropriate context instead of introducing another page-specific design language.
