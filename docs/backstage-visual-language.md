# Katwed Backstage Visual Language

Katwed has two deliberately distinct but related environments. The live Presentation and Player are the expressive **stage**. Authenticated host routes are the quiet, precise **backstage** used to prepare and operate that stage.

## Application shell and surfaces

The authenticated shell uses compact navigation with a clear current location. Its surfaces remain neutral so quiz identity appears only in library artwork, previews and visual pickers. Host chrome never changes with the selected quiz theme. Restrained borders and shallow depth communicate hierarchy; primary actions receive the strongest colour.

## Library, editor and settings

The Dashboard treats each quiz as a saved creative project. Cover artwork or a theme-derived fallback leads the card; Play and Edit remain immediate while Duplicate, Export and Archive are subordinate.

The editor is a desktop-first workspace with a compact question navigator, useful audience preview and structured settings. Adding a question uses an accessible modal picker. Presentation and Player preview modes use Pass 2 inside a neutral frame. Quiz Settings separates Game, Appearance and Answer colours; changes stay in the existing draft and Save workflow.

## Controller

The Controller is a production console. The compact Presentation preview remains dominant while the control rail shows the active phase, its one important action, compact time/answer/connection status, player presence and Up next. Head-to-Head clearly communicates its player-controlled progression.

## Density, motion and access

Backstage uses dense-but-comfortable spacing, consistent control heights and bounded laptop scroll areas. Narrow layouts stack rather than force microscopic columns. Motion is short and uses Pass 1 timing; reduced-motion removes non-essential movement. Focus-visible treatment, semantic headings, labelled fields, non-colour selected states, accessible modal behaviour and readable contrast remain mandatory.

Pass 3 adds no database migration, quiz rule, audio system, external UI framework or generated image asset. Pass 1 remains the foundation and Pass 2 remains authoritative for live-game rendering.
